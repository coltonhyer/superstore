- **Spec references:** `docs/specs/review-loop.md` (`R4`–`R19`).
- **Deliverable:** A single concise plugin-level shared reference `plugins/delivery/references/review-loop.md` covering the bounded 3-round review loop, reviewer-failure fallbacks, explicit definition of `independent`, and managing-agent checkable finding dispositions across all `delivery` review gates.
- **Prerequisites and order:** None (builds on Plan 1's `.eval/references/` copy and link/command tests). Runs first so T2 and T3 can link `../../references/review-loop.md` with every link immediately resolving.
- **Relevant paths and patterns:**
  - Create `plugins/delivery/references/review-loop.md` (linked by skills as `../../references/review-loop.md`).
  - **Single-skill eval & depth constraints:** Include zero Markdown links into `../skills/...` and zero links to other references (references stay one level deep per `REVIEW.md`). Include zero fenced shell blocks so `tests/test_skill_commands.py` stays cleanly covered.
  - Cover every shared rule in `docs/specs/review-loop.md` (`R4`–`R19`) and `REVIEW.md:18-19`:
    1. **Loop rules (`R7`–`R14`):** Fresh reviewer context with no parent history (explicitly disabling parent history such as `fork_turns: "none"` on hosts exposing that control); `Blocking` (correctness, requirement/scope gap, false code claim, consumer breakage, hollow guarantee, contract/gate defect) vs. `Non-blocking` (minor polish/optional improvement) severity; one-line defect class + specific instance with class-wide resolution; scope fit (*serves the ask* non-behavior-changing support work vs. *unnecessary*/*conflicts* removed without escalating, while any observable behavior or delivered-scope addition still requires user intent or autonomous `Decisions for review`); full review in rounds 1–2, diff-only from round 3 onward (supplying diff since prior round, prior findings/dispositions, and fixed classes, allowing targeted reads only within each reviewer's permitted scope to verify class-wide fixes or code claims); clean-round rule (no blocking edits from any reviewer; any blocking edit at a multi-reviewer gate re-runs all reviewers for that gate; non-blocking findings recorded without forcing another round); round-3 stop -> step back to check scope growth or recurring-class design flaw -> apply any redesign -> one final round (diff-only for targeted edits; full artifact when a redesign was applied); and final-round escalation (record remaining non-blocking findings; halt progression and escalate on any unresolved blocking finding not `Dismissed` with checkable evidence, including halting autonomous mode rather than promoting to `stable`).
    2. **Independence definition & reviewer-failure fallbacks (`R4`–`R6`, `REVIEW.md:18-19`):** Explicitly define a review as **`independent`** only when usable contract output (structured findings or an explicit no-material-findings result) is received and read from a distinct launched reviewer — never a self-review fallback. State that a running reviewer has not failed and tool/agent status without contract text is not usable output. Include a compact fallback scenario table covering interactive no-subagent hosts (disclosed self-review across rounds within normal cap/escalation), interactive subagent-capable hosts (once-per-gate disclosed self-review for each missing role without retrying the failed dispatch; halt and escalate if fallback cannot complete or a later round fails after the one-time fallback is spent), and autonomous mode (mandatory independent review; never promote on author self-review; halt immediately if unavailable, fails, or returns unusable output).
    3. **Checkable finding dispositions (`R15`–`R19`):** Managing agent (never reviewer) assigns every finding one disposition in conversation or report (never inside the spec or plan): `Addressed` (mandatory `Blocking`, optional `Non-blocking`; optional code edits still require fresh verification and recording; record where changed and how defect class resolved), `Elevated` (requires user intent or facts outside readable files; blocks interactive approval or follows autonomous conservative resolution), `Dismissed` (wrong based on exact checkable evidence the reviewer could have read — file+symbol or decision in artifact; *"This was intentional"* is never valid; a fresh reader's inability to follow a spec or plan is never dismissed), and `Declined` (`Non-blocking` only, true but minor, short rationale, recorded without editing or triggering another round). Include the no-appeasement-prose rule (`R19`).
  - Must pass `rumdl` (`plugins/**/*.md`).
