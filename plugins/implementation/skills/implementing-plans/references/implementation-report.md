# Implementation report contract

The assigned implementer writes this report for the supervisor. It describes
implementation and evidence; it does not approve work or update execution
state.

```markdown
# <task ID> implementation report

- **Approved context:** exact plan and spec locators, task brief/excerpts, and
  execution authorization.
- **Scope:** assigned paths and any preserved unrelated working-copy changes.
- **Changes:** implemented behavior and relevant paths.
- **Recorded result:** exact revision identifier or range; `not recorded` with
  the recording failure when applicable.
- **Verification:** exact commands or observations, actual results, and the
  state/revision they apply to.
- **Concerns and gaps:** failed, stale, unavailable, or unrun checks; scope or
  context uncertainty.
- **Status:** `reported for review`, `blocked`, or `incomplete` — never
  `complete` solely from this report.
- **Next action:** the concrete supervisor decision, review, correction, or
  recovery needed.
```

Use `reported for review` only after verification and successful recording.
When verification or recording fails, preserve the recoverable state and say
why completion cannot be claimed.
