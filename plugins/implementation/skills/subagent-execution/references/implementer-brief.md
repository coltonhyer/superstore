# Implementer brief

The supervisor gives a fresh implementer one bounded brief:

```markdown
# <task ID> implementer brief

- **Authorization and approved context:** exact task excerpt plus only the
  applicable plan/spec excerpts and earlier approved decisions.
- **Scope and interfaces:** allowed paths, relevant repository conventions,
  starting state, and unrelated work that must remain separate.
- **Workspace:** assigned workspace and active-VCS instructions.
- **Required process:** read `implementing-plans`; verify before recording;
  record only the verified task change; write the implementation report.
- **Report destination:** <execution-relative report path>.
- **Return boundary:** return the report and evidence to the supervisor; do not
  dispatch, review, adjudicate, update execution state, publish, or expand scope.
```

The brief is the worker's context boundary, not a request to explore archives or
load the complete execution record. A repair brief names the finding, its
evidence, the affected range, and the required correction/check.
